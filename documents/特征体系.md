## 1、MEMF 特征体系



MEMF 构建了 **5 类模态 × 3 类实体 + 2 类跨实体模态** 的特征矩阵。核心设计逻辑是：**同一模态在不同实体上的语义不同，必须按实体分别组织**。

text

```text
模态类型          实体归属           符号
─────────────────────────────────────────────
文本 T            主播/商品/直播间     T^An, T^Co, T^St
图像 I            主播/商品/直播间     I^An, I^Co, I^St
数值 N            主播/商品/直播间     N^An, N^Co, N^St
音频 A            跨实体（无归属）     A
视频 V            跨实体（无归属）     V
标签 Sales         目标变量            Sales
```

### 1）主播实体特征

| 属性            | 模态 | 描述                           |
| :-------------- | :--- | :----------------------------- |
| anField         | 文本 | 主播在平台所有直播间的领域汇总 |
| anCategory      | 文本 | 主播在平台的预定义类目         |
| anNick          | 文本 | 主播昵称                       |
| anTags          | 文本 | 主播在平台上的标签             |
| anIcon          | 图像 | 主播头像/形象图                |
| anView30        | 数值 | 近 30 天直播观看量             |
| anAvgComment    | 数值 | 所有直播场均评论数             |
| anAvgLike       | 数值 | 所有直播场均点赞数             |
| anCommentCount  | 数值 | 所有直播总评论数               |
| anFansCount     | 数值 | 主播粉丝总数                   |
| anFavoriteCount | 数值 | 收藏该主播的粉丝数             |
| anLikesCount    | 数值 | 所有直播总点赞数               |
| anScore         | 数值 | 平台对主播能力的评分           |

**特征逻辑**：前 4 项文本特征描述"主播是谁"（身份），anIcon 是"主播长什么样"（形象），后 8 项数值特征量化"主播影响力有多大"（历史表现）。共同刻画主播的**影响力（influence）**。

### 2）商品实体特征

| 属性           | 模态 | 描述           |
| :------------- | :--- | :------------- |
| comTitle       | 文本 | 商品名称       |
| comDescription | 文本 | 商品折扣描述   |
| comBrand       | 文本 | 商品品牌       |
| comShop        | 文本 | 提供商品的店铺 |
| comCategory    | 文本 | 商品所属类目   |
| comImage       | 图像 | 商品图片       |
| comCouponPrice | 数值 | 商品折扣价     |
| comPrice       | 数值 | 商品原价       |

**特征逻辑**：5 项文本特征构成商品的**信息画像（informational profile）**，comImage 提供视觉感知，2 项价格数值直接关联购买决策。注意 MEMF 对商品特征的特殊处理——因为一场直播有 M 件商品（场均 87.39 件），商品特征形成一个 **M × (Lt+Ln+Li) × D̂ 的四维张量**，这正是 QuadTransformer 要解决的核心问题。

### 3）直播间实体特征

| 属性        | 模态 | 描述                 |
| :---------- | :--- | :------------------- |
| strTitle    | 文本 | 直播间名称           |
| strTag      | 文本 | 直播间在平台上的标签 |
| strIcon     | 图像 | 直播间图片           |
| strDuration | 数值 | 直播时长             |

**特征逻辑**：直播间特征最精简，仅 4 项。名称和标签提供**内容预告**（吸引观众），图片提供**视觉辨识**，时长作为**主播工作量**的参考信息。

### 4）跨实体特征

| 属性   | 模态 | 描述                     |
| :----- | :--- | :----------------------- |
| Videos | 视频 | 一系列直播片段           |
| Audios | 音频 | 一系列直播音频           |
| Sales  | 数值 | 直播商品销量（目标变量） |

**关键特性**：视频和音频**不隶属于任何单一实体**，而是跨实体的复合载体——视频同时包含主播形象、商品浮窗、直播间背景；音频承载主播的情绪、语调、意图。

## 特征提取方法体系

每种模态用不同的预训练模型提取，形成**特征提取链**：

| 模态 | 提取模型          | 输出表示         | 预处理                         |
| :--- | :---------------- | :--------------- | :----------------------------- |
| 文本 | **BERT**（微调）  | 固定长度语义向量 | 分词 → 去停用词 → 特殊字符处理 |
| 图像 | **ResNet50**      | 视觉特征向量     | 统一尺寸 + 归一化              |
| 数值 | **MLP**（可训练） | 非线性特征       | 对数变换（仅销量）             |
| 视频 | **VideoMAE**      | 时空特征         | 分段提取                       |
| 音频 | **Wav2Vec 2.0**   | 高维特征         | 重采样到目标采样率             |

**文本**：BERT 双向架构捕捉上下文语义，微调以适应不同实体下的文本内容。

**图像**：ResNet 的残差连接机制精确捕获复杂视觉信息。

**数值**：MLP 深层结构 + 非线性激活，从复杂数值数据中学习隐藏关系（如粉丝数与销量的非线性关联）。

**视频**：VideoMAE 是 SOTA 视频特征提取工具，捕获时空特征。

**音频**：Wav2Vec 无监督学习，自动捕获高阶统计特征，获得丰富的语义表示（主播情绪、语调）。



## 2、LiveLens 特征体系

特征体系由**专家访谈驱动**构建，通过 3 轮半结构化访谈 6 位领域专家（2 位头部主播、2 位专业主持人、1 位 MCN 营销总监、1 位平台专家）共识收敛出 **16 个跨模态指标**，覆盖视觉、音频、文本三大模态。

#### 1）视觉特征（6 个）— 捕捉主播与直播环境的呈现质量

| 特征                             | 含义                              | 量化方法                                 |
| :------------------------------- | :-------------------------------- | :--------------------------------------- |
| **Emotion（情绪）**              | 夸张情绪表达（快乐/惊讶）的占比   | VGG-Face2 面部表情识别（微笑/惊讶/皱眉） |
| **Resolution（分辨率）**         | 视频清晰度                        | 直接计算                                 |
| **Motion Amplitude（动作幅度）** | 主播上肢运动幅度（拿取/展示产品） | MoveNet 实时关键点检测 + 平均幅度计算    |
| **Scene（场景构图）**            | 直播环境与产品风格/属性的对齐度   | 视觉场景元素 vs 产品属性对比             |
| **Frame Rate（帧率）**           | 视频流畅度                        | 直接计算                                 |
| **Host Appearance（主播外观）**  | 主播面部吸引力（影响信任与兴趣）  | 自动化面部吸引力评估 API                 |

#### 2）音频特征（5 个）— 捕捉主播的语音表现力

| 特征                        | 含义                             | 量化方法                   |
| :-------------------------- | :------------------------------- | :------------------------- |
| **Speech Rate（语速）**     | 语速与最优值 7 词/秒的偏离度     | 计算与 7 words/sec 的偏差  |
| **Pitch（音调）**           | 略高于自然基线的音调（增强感知） | 设定阈值，计算高音使用比例 |
| **Pitch Range（音调范围）** | 音调变化范围（避免单调）         | 测量音调变化范围           |
| **Volume（音量）**          | 平均音量水平（吸引注意）         | 平均音量计算               |
| **Intonation（语调）**      | 句末升调频率（表达力关键）       | 分析升调频率               |

#### 3）文本特征（5 个）— 捕捉主播话语的说服力

| 特征                                   | 含义               | 量化方法               |
| :------------------------------------- | :----------------- | :--------------------- |
| **Entertainment Value（娱乐价值）**    | 幽默元素提升参与度 | 识别脚本中的幽默元素   |
| **Scarcity Marketing（稀缺营销）**     | 限量供应等稀缺话术 | 表达力检测             |
| **Personalized Content（个性化表达）** | 主播特质化语言模式 | 检测独特语言模式       |
| **Discount（折扣信息）**               | 价格折扣相关内容   | 表达力检测             |
| **Interaction（互动表达）**            | 互动语言频率       | 计算脚本中互动语言频率 |

### 特征提取方法

#### 文本管线

```text
直播音频 → Whisper 转写 → LLM 提取说服性话语模式 → f^t_i ∈ ℝ^dt
```

- **Whisper**：将直播音频转写为文本
- **LLM + Prompt Engineering**：基于专家访谈整理的销售话术参考集，通过提示工程让 LLM 识别稀缺营销、价格敏感促销、情感丰富叙事等模式
- **编码**：用 LLM 末层表征编码为稠密向量，同时保留语言意义和话语结构

#### 音频管线

```text
Wav2Vec 2.0（语义嵌入）+ Librosa/OpenSMILE（低级描述符）→ f^a_i ∈ ℝ^da
```

- **Wav2Vec 2.0**：提取语义丰富的声学嵌入
- **Librosa / OpenSMILE**：计算 MFCC（梅尔倒谱系数）、音高轮廓、振幅变化、声音微光（shimmer）等基础参数
- **融合**：拼接深层上下文嵌入与手工低级描述符，综合表征语音内容和韵律变化

#### 视觉管线

```text
DINOv2（场景）+ VGG-Face2（表情）+ MoveNet（姿态）→ f^v_i ∈ ℝ^dv
```

| 模型          | 用途                                             |
| :------------ | :----------------------------------------------- |
| **DINOv2**    | 自监督视觉 Transformer，编码场景级视觉上下文     |
| **VGG-Face2** | 面部表情识别（微笑、惊讶、皱眉）                 |
| **MoveNet**   | 实时关键点检测，监控身体姿态、手臂运动、头部手势 |
| **手工特征**  | 手势幅度、运动频率、注意力焦点                   |

#### 统一拼接

三个模态的向量拼接为每个片段的统一多模态嵌入

**特征与销售的关联更多是非线性**的：

| 排名 | 特征                            | 模态 | Pearson | Spearman  |
| :--- | :------------------------------ | :--- | :------ | :-------- |
| 1    | Speech Rate（语速）             | 音频 | 0.414   | **0.928** |
| 2    | Emotion（情绪）                 | 视觉 | 0.182   | **0.654** |
| 3    | Scene（场景）                   | 视觉 | 0.173   | 0.612     |
| 4    | Interaction（互动）             | 文本 | 0.145   | 0.573     |
| 5    | Entertainment Value（娱乐价值） | 文本 | 0.148   | 0.527     |
| 6    | Resolution（分辨率）            | 视觉 | 0.123   | 0.521     |

**核心洞察**：

- **语速是绝对主导特征**（Spearman ρ=0.928），印证了专家"7 词/秒最优语速"的访谈结论
- 消融实验中音频模态单独使用即达 𝑅²=0.328（三模态中最高），与语速的强相关一致
- 文本特征（娱乐、互动、稀缺营销）单独预测力较弱，但作为**补充信息**与音频/视觉融合时贡献显著



## 3、主播声誉的多模态直播销量预测

本文特征体系的核心逻辑：**传统电商的"卖家声誉"是单一历史评分，而直播电商的"主播声誉"是历史声誉 + 实时声誉信号的融合**。这一设计是全文的方法论基石。

从直播记录中直接提取的 6 个数值特征，作为基线特征集 $ϕ(X1)$：

| 维度                  | 特征                                                         | 类型                            |
| :-------------------- | :----------------------------------------------------------- | :------------------------------ |
| **基础数值信息**      | 讲解时长、折后价格、新增粉丝数、峰值观看人数、点赞数、产品数 | Numerical                       |
| **历史声誉**          | 平台记录的主播历史声誉评分                                   | Numerical                       |
| **文本-图像声誉信号** | 产品描述文本、展示图像、文本-图像相似度                      | Textual / Visual / Numerical    |
| **弹幕声誉信号**      | 弹幕数量、弹幕情感均值、弹幕语义表示                         | Numerical / Numerical / Textual |

### 方法论细节

#### A-tiFSR 模型（文本-图像声誉信号提取）

三个组件构成：

- **文本表示**：使用预训练 **ELECTRA**（BERT变体）对产品标题文本编码，padding至512 tokens，输出256维向量 E∈Rm×n*E*∈R*m*×*n*
- **图像表示**：使用预训练 **NASNet** 提取视觉特征，输入尺寸 (331, 331, 3)，输出4032维向量 V*V*
- **文本-图像相似度推理**：采用 **SGRAF** 模型的 SGR（Similarity Graph Reasoning）部分，捕获全局对齐（文本↔整图）和局部对齐（文本词↔图像区域），通过图推理融合全局和局部相似度，输出最终相似度表示

> 预训练模型选择经过对比实验（附录A）：ELECTRA 优于 BERT/SBERT/RoBERTa/ViLBERT；NASNet 优于 ResNet/DenseNet/VGGNet/MobileNet V2

#### MCFF 弹幕细粒度分析框架

**弹幕三分类**：

| 类别                       | 内容                     | 示例                       |
| :------------------------- | :----------------------- | :------------------------- |
| **K1 - 普通重复弹幕**      | 口令红包等引发的重复内容 | "666"、"冲冲冲"            |
| **K2 - 主播/直播相关弹幕** | 与主播个人或直播流程相关 | 含"主播"、"助播"等关键片段 |
| **K3 - 产品相关弹幕**      | 与产品本身相关的讨论     | 产品质量、功能、价格讨论   |

**三类弹幕各自提取三维特征**：

- **数量（N）**：每类弹幕的计数
- **文本表示（T）**：语义编码后的向量表示
- **情感均值（S）**：通过训练的弹幕情感分析模型计算

#### 4.3 特征融合与预测

所有特征映射到同一语义空间，通过多个全连接层 + ReLU激活层实现预测。优化方式：SGD，batch size=64，初始学习率=0.003，dropout=0.2，10折交叉验证。
