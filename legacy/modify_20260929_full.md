### 五、舍弃决定（2026-09-29 定案）：**`type=6` 不作为数据字段**

**决定**：`type=6` 不再作为数据字段/特征使用；相关代码全部回退，验证过程只保留在本文件。

#### 依据一：**获取完整性不可测**（决定性）

设计了**非循环的翻转见证检验**：任何 `User` 快照都带 `user_fans_club_status`，若同一用户被
观测到 `status=1 → 2`，则两点之间**必然**发生过一次点亮，故**必然**有一条 type=6；检查区间内
是否抓到该用户的 type=6，即可判定捕获率。见证只取**非 fansclub 来源**，避免自证。

结果：**0 个可用翻转对**（离线语料与游客态实连 10min 两路都是 0）。

原因不是漏采，而是**方法在本语料上没有检验力**：

| 场次（连线均连续） | 多次观测用户 | status 变过 |
|---|---|---|
| 0928_173058 / 193438 / 201351 / 203441 / 211329 / 212944 | 239 / 89 / 77 / 58 / 47 / 17 | 0 / 0 / 0 / 0 / 0 / 0 |
| 0929_092745 | 447 | 1 |
| 0929_094455 | 17 | 0 |
| 0929_094731 | 404 | 1 |

**1395 个多次观测用户里只有 2 个变过，且都不是 1→2。** 即**一场连续连线内 status 基本是冻结值**。
而要见证翻转，需「同一用户两次观测跨过翻转」——实测 **90~97% 的用户一场只出现一次**
（游客态 10min 实连：5719 用户里仅 657 个有 ≥2 次观测 = 11.5%），且这些重复观测还是**秒级挤在
一起**的。10min 窗口根本装不下一次翻转。

补充：`enter` 观测到的 2147 个用户与 `chat` 观测到的 650 个，**交集仅 30 个（Jaccard 1.08%）**
——我们的**人均观测密度极低**，这是 0 对的根本原因，不是服务端漏采。

#### 依据二：**到达高度爆发，绝对条数不可用**

| 场次 | type=6 | 跨度 s | 相邻间隔特征 |
|---|---|---|---|
| 201351 | 44 | 207 | 最大 24s，**9 对间隔 ≤1s** |
| 092745 | 3 | 457 | 最大间隔 **363s** |
| 203441 | 7 | 149 | 33/32/30/25/24/5，较均匀 |

若按 44 条/207s 的速率，457s 内该出约 97 条，实际 3 条 —— **40 倍方差不是小样本噪声，是真实聚集**。
叠加上「完整性不可测」，条数的方差里房间属性/采样率/成簇效应**三者无法分离**。

#### 依据三：语义本身就只是**推断**

定标原本依赖三条：① content 恒空（wire 顶层无 `f3`）——**硬事实**；② `status` 1→2 翻转——
**已被依据一推翻**（3 个所谓翻转全跨隔夜离线缺口，见上面的作废声明）；③ ±30s 无邻近行为
（75/75）——硬事实但**非排他**。剩下能支撑「点亮」的证据是：75/75 的 type=6 快照都是 `status=2`，
而成员快照基线是 96% 为 2（p≈0.05，**支持而非证明**）。

#### 后续方向（已评估、未实施）

既然 type=6 不能当事件计数，粉丝团的**时序**维度改为**对累计值做滑动窗口差分**：

- `fansclub_member_count` / `fansclub_user_count` 实测**单调不减**（合法累计计数器），差分合法；
  但它们是 `len(self.fansclub_users)`（**我们观测到的集合**），差分**只消除稀疏、不消除采样**。
- 真正的收益在**比值**：`Δ未点亮 / (Δ未点亮 + Δ已点亮)` 这类量，采样因子近似约掉，
  且密度远高于事件计数 —— 游客态 10min 实测 **60s 窗下新观测成员 292/窗**、
  新观测未点亮成员 12.4/窗（**0 个空窗**），而 type=6 只有 **0.2 条/窗**。
- 顺带修掉现存 `fansclub_member_ratio` 的钝化缺陷：它是**累计集**比率，实测 80 秒后就锁死在
  0.50 附近、之后 9 分钟几乎不动，对预测窗口没有分辨力。

  ② 新到达的未点亮占比**渠道混合敏感**（enter 2.6% / chat 9.0% / like 11.8%），须固定渠道混合；
  ③ `total_pv` 是 `'257.8万'` 字符串（量化步长 1000，≥60s 窗才可用），`viewer_count` /
